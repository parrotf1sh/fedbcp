# FedHPro 两种子批量实验

在实验机项目根目录、已安装项目依赖的环境中运行：

```bash
python scripts/run_fedhpro_experiments.py
```

默认单 GPU 串行执行 44 次训练，每次 300 轮，训练种子 `[2022, 2023]`。
采用用户确认的减量服务器预算、确定性 DSA 和已有独立客户端快照 B 修正。
这是共同实验协议下的预算适配版本，不能标为原论文或原默认配置复现。

## 实验矩阵

| 类别 | 数据集 | 变化参数 | 次数（含两个种子） |
| --- | --- | --- | --- |
| 主实验：LDA | CIFAR10、CIFAR100、Tiny-ImageNet | α=0.03/0.1/0.3 | 18 |
| 主实验：分片 | 同上 | 每客户端分片数 2/4/6 | 18 |
| 补充：参与率 | CIFAR100，LDA α=0.1 | q=0.05/0.2 | 4 |
| 补充：本地更新 | CIFAR100，LDA α=0.1 | E=1/10 | 4 |

共 22 个条件、44 次训练。q=0.1、E=5 的共同基准复用主实验；不额外加入消融或搜索。
只改变训练种子，划分种子固定 `19940817`，抽样仍为逐轮 `numpy.seed(round_index)`。
共享 18 份划分缓存和 LDA 统一补足规则；缺失数据集自动下载。

N=100、默认 q=0.1、E=5、batch=50；SGD lr=0.01、momentum=0.9、weight_decay=1e-5；
公共 StepLR 每通信轮乘 0.99。CIFAR 使用 `fedavg_cifar`，Tiny 使用 `fedavg_tiny`，无投影头。
所有参数集中在脚本头部。

## 明确的服务器预算

| 脚本参数 | 当前批量值 | 原默认值 |
| --- | --- | --- |
| `META_ROUNDS`：每轮元原型匹配步数 | 20 | 100 |
| `META_EPOCHS`：每轮新分类头训练 epoch | 10 | 100 |
| `ROUNDS_OF_HP`：每轮超原型匹配步数 | 10 | 30 |

保留每类超原型 5 个、元原型 50 个、本地温度 0.05、原型学习率 0.1、
新分类头学习率 0.01、分类头 batch size 50、每次每类真实样本上限 100、
repeat_num=1、use_margin=False、dis_metric=matching、DSA 及其现有增强参数。
原型/新分类头优化器的独立学习率固定，不套用客户端 StepLR。

分类头每轮更新数为 `META_EPOCHS * ceil(C * META_LENGTH / META_BATCH_SIZE)`。
默认批量配置下，CIFAR10/CIFAR100/Tiny-ImageNet 分别为 100/1000/2000 次更新，
对应原默认的 1000/10000/20000 次。服务器梯度匹配也有高阶求导开销，
减量后仍不保证与 FedAvg 同等耗时；不以估算替代实际计时。

恢复原预算时将上述三项分别设为 100/100/30。一次队列只运行选定设置，
不会自动把两套预算都加入 44 次训练。任务名称包含具体预算和 DSA 模式；
tags 区分 adapted-budget/source-budget，完整配置参与任务哈希，避免错用旧结果。
即便恢复原预算，B 修正及公共数据/模型协议仍然存在；恢复预算不等于完全复现原仓库。

## 确定性 DSA

批量默认 `DSA_SEED_MODE="deterministic"`。使用 SHA-256 对版本标识和
`[训练种子, 零起始轮次, 客户端编号, 重复编号, 类别]` 编码，取摘要前 8 字节的大端整数
模 `2**31` 得到 seed。服务器在任何 DSA 操作前捕获 Torch 初始训练 seed，
不使用会随 DSA 重置改变的当前 seed，也不使用 Python hash() 或系统时间。

只替换 DSA seed 来源，增强算子、执行顺序、同 batch 共享随机参数以及全局 Torch
重置方式均保留。训练种子因此也控制 DSA，不再增加独立的种子网格。
同一协议重跑的 seed 派生确定，但不承诺跨硬件/软件环境逐位一致。
如果显式选择 `wall_clock`，恢复原 `int(time.time()*1000)%100000` 行为，
此时固定训练 seed 不能控制全部随机性；名称、tags、config 会明确记录。
单次 JSON 入口默认仍使用原预算和 wall_clock 模式。

## 保留的算法流程

详细公式与边界见 [FedHPro 移植说明](../src/algorithms/fedhpro/README.md)。

1. 每个参与客户端先在旧 meta head 下收集每类真实特征/分类头梯度。
2. 恢复当轮原全局分类头，用旧超原型优化本地模型。每次重建 SGD 并清空状态。
3. 上传独立客户端模型快照，按样本量执行先乘、求和、再除的聚合。
4. 真实梯度按每类贡献客户端等权平均，更新元原型。
5. 每轮随机初始化新线性头，在元原型上训练后替换聚合分类头，不 warm-start。
6. 加载新全局分类头后匹配特征梯度更新超原型，下一轮才下发。

损失保持 `CE + HPCL + HPAL`，包括 HPCL 额外除以当前 batch size、不同的归一化顺序、
原始 matching 距离及 create_graph=True。不加入新损失权重或数值 clamp。
缺类梯度不补齐；模型上传使用已有 B 修正的独立快照，不能恢复为共享张量覆盖。
梯度收集仍按原方式物化客户端数据并逐类抽样，不改变样本或增强的访问顺序。

## 指标与通信

每轮评估一次分类头修正后的全局模型；批量模式跳过训练前及额外客户端统计评估。
逐轮记录 Top-1、测试 CE、Macro-F1、逐类召回、最差 20% 类别平均召回，
以及在线训练准确率、按实际处理样本数加权的 CE/HPCL/HPAL/总损失。
日志加权不改变梯度使用的损失归约。

`fedhpro/*_loss_last_step` 表示元原型匹配、新分类头训练、超原型匹配的最后一步损失，
不是整个阶段的均值；另记录有效梯度类别数、原型张量容量和每轮分类头更新数。

五段计时分别覆盖真实梯度收集、本地训练、元原型匹配、分类头重训、超原型匹配。
CUDA 在计时边界同步。它们是整轮训练时间的子项，不应再次相加；
模型复制、聚合和其他控制开销包含在整轮时间内，未必包含在五段计时之和中。
全局评估时间单独记录。

通信量为逻辑张量载荷：

- 公共部分：全局模型下行、客户端模型上行、优化器张量下行。
- FedHPro 额外下行：旧 meta head 与超原型；全局骨干只传一次，meta 模型在客户端组合。
- FedHPro 额外上行：每类特征梯度，以及每类分类头 weight/bias 梯度。
  两个稀疏梯度字典分别计 int64 类别 ID；标签顺序已知的稠密超原型不另传类别向量。
- 元原型留在服务器，不计为下载；模拟器重复加载完整参数不重复计网络流量。

不包括协议、形状等控制元数据或本机 CPU/GPU 拷贝。各分项分别记录，
公共模型流量只计一次；不能用仅模型上下传的数字代表 FedHPro 总通信。

W&B 项目默认 `Point1`，每次独立 run，自动记录名称、tags、有效配置和划分指纹。
最终汇总包括最后一轮、最后 10 轮平均准确率、分类指标、阶段耗时和通信量。
aggregate.csv 汇总两个种子的均值和样本标准差，并列出成功/预期种子数。
与三种子 FedAvg 配对比较时使用共同的 2022、2023 两个种子。

## 输出、失败处理与验证

默认输出 `fedhpro_experiments/`，只保存任务清单、配置、日志、状态、metrics.csv、
clients.jsonl、划分统计、summary.json 和 aggregate.csv。模型、分类头、原型、梯度、
优化器只驻留内存，不保存 checkpoint、权重文件或模型 artifact。
数据划分缓存 NPZ 仅包含索引及元数据。
单任务异常后继续下一任务，成功任务默认跳过；失败重跑从头训练并新建 attempt/run。
Ctrl+C 停止当前训练和队列，不同时启动其他 GPU 队列。

```bash
# 可选：使用 8 个 CPU worker 准备共享划分
python scripts/prepare_partitions.py --source fedhpro --workers 8

# 只生成清单，不训练、不下载、不连接 W&B
python scripts/run_fedhpro_experiments.py --dry-run

python scripts/run_fedhpro_experiments.py --data-root /data --output-root /results/fedhpro
```

非训练检查覆盖任务配对、缓存复用、错误继续、成功跳过、原默认配置保留、
跨进程确定性种子、样本加权日志、实际继承的独立快照、阶段顺序、
新分类头评估和通信载荷。流程/数值检查使用 NumPy 和接口替身。
未运行 PyTorch/GPU 前反向、数据下载、W&B 联网、完整训练或小规模冒烟训练，
不据此声称收敛、真实运行速度或数值等价已经验证。
